# NCCL Release 2.7.3

{#release-notes-section_n2q_kp4_phb}
This is the NCCL 2.7.3 release notes. For previous NCCL release notes, refer to the [NCCL Archives](https://docs.nvidia.com/deeplearning/sdk/nccl-archived/index.html).

## Key Features and Enhancements

This NCCL release includes the following key features and enhancements.

-   Added support for A100 GPU and related platforms
-   Added support for CUDA 11
-   Added support for send/receive operations \(beta\)

## Compatibility

NCCL 2.7.3 has been tested with the following:

-   Deep learning framework containers. Refer to the [Support Matrix](https://docs.nvidia.com/deeplearning/frameworks/support-matrix/index.html) for the supported container version.
-   This NCCL release supports [CUDA 10.1](https://docs.nvidia.com/cuda/archive/10.1/index.html), [CUDA 10.2](https://docs.nvidia.com/cuda/archive/10.2/index.html), and [CUDA 11.0](https://docs.nvidia.com/cuda/archive/11.0_GA/).

## Known Issues

Send/receive operations have a number of limitations:

-   Using send/receive operations in combination to launch work on multiple GPUs from a single process can fail or hang if the GPUs process different amounts of data. Setting `NCCL_LAUNCH_MODE=PARALLEL` can work around the issue, but can also cause other problems. For more information, see the [NCCL User Guide](https://docs.nvidia.com/deeplearning/nccl/user-guide/index.html) section **Troubleshooting** &gt; **Known Issues** &gt; [Concurrency Between NCCL and CUDA calls](https://docs.nvidia.com/deeplearning/nccl/archives/nccl_273/user-guide/docs/troubleshooting.html#concurrency-between-nccl-and-cuda-calls-nccl-up-to-2-0-5-or-cuda-8).
-   Aggregation is not supported on a given source-destination pair, meaning that there can only be one send/receive per source-destination pair.
-   Each source-destination pair allocates a dedicated fifo of 4 MB \(see `NCCL_BUFFSIZE` variable\) which can use a significant amount of GPU memory at scale.
-   When using GPU Direct RDMA, each point-to-point connection will also use resources on the GPU PCI address space, which we might run out of on some models. If that happens, consider disabling GPU Direct RDMA \(`NCCL_NET_GDR_LEVEL=0`\) or reduce the per-peer buffer size \(`NCCL_BUFFSIZE`\).
-   Send/receive operations are not yet optimized for the DGX-1 NVLink topology.
